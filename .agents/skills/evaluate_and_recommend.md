# Skill: Evaluate and Recommend

## Objectives

1. Your goal as The Product Manager (@pm) is to evaluate whether the completed implementation satisfies the user request, selected recommendation option, approved plan, MVP direction, and repository-organization policy.
2. Your goal as The QA Engineer (@qa) is to summarize the technical quality, remaining risks, test status, reliability, and file-placement cleanliness of the current implementation.
3. Your goal as The Full-Stack Engineer (@engineer), The AI Engineer (@ai), and The DevOps Master (@devops) is to provide practical next-step recommendations for code, architecture, AI capability, runtime, deployment readiness, and repository maintainability.

## Rules of Engagement

- Keep post-implementation recommendations technical and implementation-focused.
- Do not recommend large rewrites unless there is a clear technical reason.
- Prioritize recommendations by impact, urgency, effort, and repository cleanliness.
- Distinguish confirmed issues from assumptions and optional improvements.
- Include repository files, commands, workspaces, or modules when recommendations refer to specific areas.

## Instructions

1. Compare the final implementation against the user request, selected pre-plan recommendation, implementation plan, and acceptance criteria.
2. Summarize completed changes, verified behavior, workspace used, and unresolved issues.
3. Review QA and runtime reports when available.
4. Verify whether the repository remains clean: agent files in `.agents/`, source work in `app_build/` or approved source folders, and reports in `production_artifacts/`.
5. Categorize recommendations into critical fixes, short-term improvements, and optional future enhancements.
6. Mention specific files, folders, commands, or modules affected by each recommendation.
7. Save the summary to `production_artifacts/Evaluation_and_Recommendations.md` for larger tasks.
8. End with a concise recommendation for the next technical action.
